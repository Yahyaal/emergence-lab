# Emergence Lab

An experimental artificial-universe explorer. It runs many small universes, each
with its own fixed rule and random initial condition. An independent
**observatory** measures what happens in each one, and a **discovery engine**
searches rule space for universes that are unusual or promising, with no
predefined notion of what "life" or "complexity" should look like.

Runs on a normal laptop: pure Python + NumPy/SciPy, no GPU, no cloud, no paid APIs.
The default experiment (100 universes × 5 generations + robustness re-runs) takes
about a minute on 4 cores.

## Quick start

```bash
git clone https://github.com/yahyaal/emergence-lab.git
cd emergence-lab
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e '.[dev]'

emergence explore                 # 100 universes x 5 generations -> lab.db
emergence serve                   # open http://127.0.0.1:8000
```

Python 3.10+ is required.

### Other commands

```bash
emergence explore --universes 100 --generations 10 --steps 800 --size 64 --seed 7 --name long-run
emergence list                    # experiments in lab.db
emergence top 1 -n 20             # highest-priority universes of experiment #1
emergence discoveries 1           # what the engine flagged, with evidence
emergence reproduce 258 326       # re-run universes from their record and verify bit-for-bit
emergence observe B3/S23 --seed 4 # measure any single rule (Conway's Life here)
emergence export 1 exp1.json      # full experiment as JSON
emergence --db other.db serve --port 8001
pytest                            # test suite
```

## Dashboard

* **Gallery**: every universe's final state, sortable by Pareto priority, novelty,
  activity, moving structures, persistent shapes, randomness, damage spreading,
  transient length, local periodicity. Filter by class or role. Tick **Animate**
  to watch them all run.
* **Viewer**: click a universe to watch it. Play/pause (Space), step (← →), rewind,
  scrub the timeline, change speed, zoom (scroll) and pan (drag). **Shift+click** adds
  up to 4 universes side by side; **Sync panels** locks their clocks together.
* **Details**: every measurement, history charts (the cursor follows the viewer;
  click a chart to jump there), the mutation lineage, and the robustness re-runs.
* **Discoveries**: candidates the engine re-tested, labelled *robust* or *seed-sensitive*.
* **Ad-hoc**: type any rule (e.g. `B3/S23`, `B36/S23`, `B2/S/C3`) to view it live.
* The URL keeps the open experiment and panels (`#exp=1&open=258,326`), so you can
  bookmark a view.

Frames are always generated by the same Python engine that ran the experiment,
replayed from the stored spec. What you watch is exactly what was measured.

## Architecture

```
emergence/
  physics/          rule families behind one interface (Physics.step / random / mutate)
    base.py           abstract interface + registry (add new physics here)
    totalistic.py     Life-like (B/S) and Generations (B/S/C) automata on a torus
  engine.py         Universe + UniverseSpec (rule, seed, size, density): deterministic, read-only state views
  observatory/      passive measurement, never writes to a universe
    measures.py       density, activity, block entropy, compression-vs-surrogate, local periodicity
    structures.py     connected-component census: still lifes, persistent shapes, movers
    recurrence.py     exact and translated global recurrence (cycle period, transient, drift)
    probes.py         damage spreading on a *forked twin*
    observer.py       turns a frame stream into metrics + descriptor + coarse class
  lab.py            the only place engine and observatory meet (one-way: frames -> observer)
  discovery.py      Pareto ranking + novelty search + mutation + robustness follow-ups
  storage.py        SQLite lab notebook
  server.py, web/   dashboard (stdlib HTTP server + vanilla JS, no build step)
  cli.py
```

**Separation of concerns.** The engine has no idea it is being observed. The
observer receives read-only views and keeps its own copies. Its own randomness
(surrogate shuffles, probe locations) comes from a separate random stream, so
measuring never changes a universe. A test (`test_observer_does_not_affect_universe`)
checks this.

**Adding new physics.** Subclass `Physics` (`step`, `random_state`, `random`,
`mutate`, `to_dict`/`from_dict`, `label`), decorate it with `@register`, and the
observatory, discovery engine, storage and replay work unchanged, as long as a
state is a 2D array of small integers. (The dashboard's ad-hoc box and frame
endpoint currently assume rule-string physics; that's the one place to generalise.)

## Methods

Established, simple estimators, each answering a different question:

| Measure | Question | Method |
|---|---|---|
| Activity, density | Is anything happening? | fraction of changed / occupied cells |
| Block entropy | How varied is local texture? | Shannon entropy of 2×2 blocks |
| Spatial & space-time compressibility | Ordered or noise-like? | zlib size ÷ zlib size of a shuffled surrogate with the same cell statistics (≈1 = noise) |
| Global recurrence | Has it settled into a cycle? | state hashing; shifted cycles via Fourier-magnitude candidates verified exactly |
| Local periodicity | Is the activity mere oscillation? | fraction of *changing* cells whose own time series has period ≤ 32 |
| Still / persistent / moving structures | Are there coherent objects? | 8-connected components; a shape counts as persistent when seen at the same place at t, t+p, t+2p, and as a mover when seen at a, a+d, a+2d at t, t+τ, t+2τ |
| Damage spreading | Ordered, chaotic, or in between? | flip one cell in a forked twin and track the Hamming distance (a discrete Lyapunov analogue) |
| Langton's λ | Static property of the rule | weighted fraction of rule-table entries that produce a live cell |

**Telling randomness, repetition and organisation apart.** Noise shows up as
compressibility ≈ 1 with damage saturating. Repetition shows up as a global
recurrence or local periodicity ≈ 1. Organised behaviour sits in between:
compressible but still changing aperiodically, with persistent and moving objects
and limited damage spread.

**Classes** (`extinct, saturated, frozen, periodic, drifting, chaotic, complex,
active`) are coarse, transparent labels for humans (see `classify()` in
`observer.py`). The discovery engine does **not** optimise them.

**Discovery engine** (`discovery.py`):

1. Every universe gets a 14-dimensional behaviour descriptor.
2. **Novelty** is the mean distance to its 10 nearest neighbours among everything
   seen so far (novelty search, Lehman & Stanley 2011).
3. **Pareto ranking** (non-dominated sorting) runs over independent objectives:
   aperiodic activity, order (1 − space-time compressibility), mover sightings,
   persistent-shape vocabulary and transient length. Nothing is summed or weighted.
   Universes that are dead, frozen or purely oscillating are recorded and shown but
   not ranked or bred from.
4. **Priority**: the Pareto rank comes first, and novelty breaks ties. Parents are
   picked by tournament selection on priority and mutated (birth/survival bits
   flipped, state count changed). 20% of each generation is fresh random rules,
   and duplicate rules are skipped.
5. **Robustness follow-up**: the top candidates, plus the single most novel
   universe, are re-run with 3 new seeds and once on a 2× larger world for 2× as
   many steps. A discovery is *robust* if it keeps the same class in every run
   and its descriptor stays close to the original.

## Reproducibility

* Each universe is fully defined by its `UniverseSpec` (rule, seed, size, initial
  density) plus the number of steps. All of it is stored, together with a BLAKE2
  hash of the final state and the full metrics.
* All randomness is seeded from the experiment's master seed: per-generation
  streams for proposing rules, and separate streams for the observatory. The same
  command with the same `--seed` produces the same experiment, whatever the number
  of worker processes (tested in `test_exploration_is_deterministic`).
* `emergence reproduce <id>` re-runs a universe and checks the final-state hash and
  every metric against the record.
* Each experiment stores its full config and environment (Python, NumPy and SciPy
  versions, platform). `lab.db` is plain SQLite, and `emergence export` writes JSON.

## Known limitations and next steps

* Objects that straddle the torus seam are split in two by the component census,
  so they are briefly lost while they wrap.
* Thresholds in `classify()` are heuristics tuned on well-known rules (Life,
  HighLife, Seeds, Brian's Brain, Day & Night, Maze, ...). They label universes for
  humans; they don't drive the search.
* 64×64 tori and 500 steps are small. Long transients (Life-like soups) can be cut
  off, so raise `--steps`/`--size` for serious runs. A 64×64 torus also has
  peculiarities: linear rules such as B1357/S1357 die out completely on
  power-of-two grids.
* Ideas: more rule families (non-totalistic/isotropic, continuous automata such as
  Lenia, particle systems), block-entropy convergence and mutual-information
  measures, a MAP-Elites archive over the descriptor, multi-seed screening during
  exploration, and a notebook for offline analysis of `lab.db`.
